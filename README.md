# yasirPublic

A public, **redacted** mirror of parts of my private `/home/yasir` repo — the shared home folder
that syncs across the machines in my homelab.

Generated by a script, not maintained by hand, so hopefully no leaks :/

Inspired by JimsGarage's docker folder, a great resource for self-hosting in general.

## What's here — 158 files

| | |
|---|---|
| `Scripts/` | 92 — Wake-on-LAN, NAS mounting, package/flatpak backup, cron logging, desktop and Steam Deck fixes |
| `compose-docker/` | 39 — Docker Compose files across 39 stacks |

## What's not here, and why

The private repo is ~165k tracked files. The overwhelming majority is excluded by
policy — **255 files** — not because anything was wrong with them:

- **`Store/`** — machine-generated backups of `/etc`, `/root` and `/sbin` from every host.
  ~164k files of raw system state. Never published.
- **The mounted config trees under `compose-docker/`** — only the compose files themselves go out.
  The service directories they mount are app state, and held most of that tree's credential matches.
- **Anything host-specific enough to be an inventory**: the per-host backup, restore and NAS-sync
  scripts, the captured crontab, the Grafana dashboard dump, the fleet bootstrap script. For the
  three script directories there is instead **one generic `example*.sh`** showing the pattern —
  which is the reusable part anyway.
- **`nutServer/`** — only the shipped `.example.conf` templates; the live configs describe the real
  UPS topology and shutdown ordering.
- Vendored upstream clones (Jitsi, Invidious's `repo/`), `Archive/` and `Z.*` experiments, `.bak`
  copies, and the publisher's own script and config.

Nothing is currently dropped for its *contents* — the content tripwires still run on every file, they simply have nothing left to catch once the directories above are excluded.


`hosts` **is** included, but with every address replaced and household/family devices removed — so
it lists the homelab machines and nothing about where they are.

## How the redaction works

Allowlist the paths worth publishing → deny by filename (`.env`, `*.key`, `id_*`, `known_hosts`,
editor state, …) → redact → **re-scan the redacted text and drop the entire file if anything still
looks like a secret**. It fails closed: a file is published only if it survives every stage.

Replaced with placeholders:

- private, tailnet and public IPs; MAC addresses; SSH public keys; email addresses; my domain
- **bind-mount volumes and storage paths** — a compose file's volume list is a map of the filesystem
- SSH private-key *filenames* — a name like `<service>_backup` advertises what a key reaches
- values of credential-bearing keys, judged by the **value** as well as the name, so an oddly-named
  one still gets caught — including the default baked into `${VAR:-default}`
- UUIDs assigned to a key, which identify a specific account or file

Placeholders like `changeme` and bare `$VARIABLE` are deliberately left intact: they carry
information and no risk.

Hostnames (`lilboi`, `docker0`, `porty`, …) are kept on purpose. With no address, domain or key
attached they're just labels, and the scripts are unreadable without them.

**Nothing here runs as-is.** It's meant to be read, not cloned and executed.
